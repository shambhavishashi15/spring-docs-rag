# Milestone 1 plan

Here's the plan for milestone 1. Nothing has been created yet.

## Versions (checked on start.spring.io today)

| Item | Choice | Why |
|---|---|---|
| Spring AI | **2.0.1** | Latest stable release. 2.1.0 is still a milestone build. |
| Spring Boot | **4.1.1** | Latest stable release, and within the range Spring AI 2.0.1 supports (4.0.0 up to, but not including, 4.2.0-M1). |
| Java | **21** | As required. The Codespace has JDK 25 installed, which can compile for Java 21 (`--release 21`), so nothing else needs installing. |
| Build | Maven, with the Maven wrapper (`mvnw`) generated by Initializr | Anyone who clones the repo uses the same Maven version. |
| Postgres image | `pgvector/pgvector:pg17` | Official pgvector image on Postgres 17. I'll pin the exact tag in step 4. |
| Chat model | `gemini-2.5-flash` | Available on the free tier and good enough for RAG answers. |

**Spring Boot 4 instead of 3:** your original brief said "Boot 3+". The latest Spring AI only supports Boot 4, so the rule you added in CLAUDE.md leads to Boot 4. That's also a good interview topic.

## Step 1: Generate the project
- Generate it with `curl` from start.spring.io: Maven, Java 21, Boot 4.1.1, packaging jar.
- **Dependencies:** only `web` and `spring-ai-openai`. The pgvector and JDBC dependencies wait until milestone 2. If I added them now, the app would refuse to start without a running database.
- **Coordinates:** groupId `io.github.shambhavishashi15`, artifactId `spring-docs-rag`, package `io.github.shambhavishashi15.springdocsrag`. Tell me if you'd prefer something else.
- **Generated test:** Initializr creates a test that starts the whole app. I'll give it a dummy API key so it doesn't need a real Gemini key.
- **How you test it:** run `./mvnw test`. The build should pass.

## Step 2: Gemini configuration (`application.yml`)
- Spring AI's OpenAI client, pointed at Gemini's OpenAI-compatible endpoint:
  - base URL `https://generativelanguage.googleapis.com/v1beta/openai`
  - API key from `${GEMINI_API_KEY}`
  - model `gemini-2.5-flash`
- **Path override:** Gemini's URL already contains the version prefix, so the client's default `/v1/chat/completions` path must become `/chat/completions`.
- **Things to check against the 2.0.1 docs:** Spring AI 2.0 changed parts of its OpenAI module, so I'll confirm the exact property names before writing them.
- **429 retries:** Spring AI has built-in retry with backoff (`spring.ai.retry.*`). I'll leave the defaults here and tune them for Gemini's rate limits in a later step.
- **How you test it:** the app starts with `GEMINI_API_KEY` set, and fails with a clear error if it isn't set.

## Step 3: `POST /api/v1/chat`
- **Request and response:** request `{"message": "..."}`, response `{"reply": "..."}`, both defined as Java records.
- **Controller:** a thin `ChatController` that uses Spring AI's `ChatClient`. ChatClient is the fluent API we'll reuse in milestone 3 for adding the retrieved context. It's a step above `ChatModel`, which is the raw model interface.
- **Deliberately left out for now:** validation and exception handling. Those are milestone 3.
- **How you test it:** a `curl` command with a sample question returns a reply from Gemini.

## Step 4: docker-compose with pgvector
- **`compose.yaml`:**
  - the pgvector image
  - database, user and password from env vars, with dev defaults
  - a named volume
  - a healthcheck based on `pg_isready`
  - port 5432
- **Extension:** an init script that runs `CREATE EXTENSION IF NOT EXISTS vector`.
- **Not wired to the app yet:** connecting the app to the database belongs to milestone 2.
- **How you test it:** run `docker compose up -d`, then run `psql` inside the container and check `\dx`. It should list the `vector` extension.
